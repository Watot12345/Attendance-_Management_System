# LAMS — Context Card
# Library Attendance Monitoring System

> One-page reference. Load this instead of all 6 docs for routine tasks.
> Read full docs only when: building new features, schema changes, security reviews, or onboarding new AI sessions.

---

## Project

| | |
|---|---|
| **Goal** | Web-based library attendance tracking via QR scan, with tardy/absence detection, excuse slips, parent email alerts, analytics, and exports. |
| **Platform** | Web app only (responsive, no native app) |
| **Users** | Student, Teacher, Staff, Admin, Parent |
| **Institution** | Single library (not multi-branch) |

---

## Tech Stack

| Layer | Tech |
|-------|------|
| Backend | Native PHP 8.2+ (`declare(strict_types=1)`) |
| Database | MySQL 8.0+ (PDO, prepared statements ONLY) |
| CSS | Tailwind CSS 3.4+ |
| JS | Vanilla ES6+ (no jQuery, no frameworks) |
| QR Scan | html5-qrcode |
| Email | PHPMailer (SMTP) |
| Charts | Chart.js |
| Auth | PHP native sessions |

**NOT used:** Docker, Redis, queues, WebSockets, PHP frameworks, JS frameworks.

## Authentication

- PHP sessions. Regenerate ID on login.
- Passwords: `password_hash($pw, PASSWORD_BCRYPT, ['cost' => 12])`
- Session timeout: 8h absolute, 24h idle
- Session cookies: `HttpOnly`, `Secure`, `SameSite=Strict`
- Login rate limit: 5 fails / 15 min, 10 fails / 1 hour

## Core Data Model (Summary)

| Table | Key Fields | Notes |
|-------|-----------|-------|
| **users** | `user_id`, `role`, `email`, `password_hash`, `status` | Auth base for all roles |
| **students** | `user_id`, `student_code`, `grade_level`, `section`, `qr_code`, `rfid_tag`, `parent_user_id` | 1:1 with users |
| **teachers** | `user_id`, `employee_id`, `department` | 1:1 with users |
| **attendance_records** | `user_id`, `record_date`, `entry_time`, `exit_time`, `direction`, `method`, `status`, `is_excused` | Status: present/tardy/absent/excused |
| **excuse_slips** | `student_user_id`, `submitted_by`, `reason`, `date_from`, `date_to`, `status`, `reviewed_by` | pending→approved/rejected |
| **parent_alerts** | `recipient_email`, `student_user_id`, `alert_type`, `status` | pending/sent/failed; processed by cron |
| **perfect_attendance_awards** | `student_user_id`, `period_start`, `period_end`, `award_type` | Generated by admin tool |
| **library_settings** | `setting_key`, `setting_value` | Config: open_time, close_time, tardy_threshold, etc. |
| **audit_logs** | `user_id`, `action`, `entity_type`, `entity_id`, `old_values`, `new_values` | All destructive actions |

**Business Rules:**
- Tardy = entry after (open_time + threshold_minutes)
- Absent = no entry by closing time (cron job marks it)
- Excused = approved excuse slip overrides tardy/absent
- Perfect attendance = zero unexcused absences AND zero tardies in period
- Parent alerts sent ONLY for unexcused tardy/absent

## API Contract

All API endpoints return:
```json
{
  "success": true,
  "message": "Human readable",
  "data": { ... },
  "errors": { "field": "message" }
}
```

AJAX headers must include: `X-CSRF-Token: <token>`

## Security Checklist (Every Change)

- [ ] CSRF token included on all POST/PUT/DELETE
- [ ] Server-side validation (never trust client)
- [ ] Prepared statements for ALL DB queries
- [ ] `htmlspecialchars()` on ALL output
- [ ] Authorization check before action
- [ ] No secrets in code (use `.env`)
- [ ] File uploads: validate type, size, rename, store outside web root
- [ ] Audit log for destructive actions

## Cron Jobs

```bash
*/5 * * * *  php /var/www/lams/scripts/cron_alerts.php      # send pending emails
30 17 * * *  php /var/www/lams/scripts/cron_absence.php     # mark absences (adjust to close_time + 30m)
0 2 * * 0    php /var/www/lams/scripts/cron_cleanup.php     # purge old data
```
